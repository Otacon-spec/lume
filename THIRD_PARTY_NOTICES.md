The Rust dependency license report is in
[`THIRD_PARTY_LICENSES.md`](THIRD_PARTY_LICENSES.md), generated by `cargo about` from
`Cargo.lock` and `about.toml`. Its dependency graph may include crates for targets or
features absent from a particular executable; it is not a binary composition inventory.
When a release includes the language-server bundle, it also ships rust-analyzer (MIT OR
Apache-2.0), Tombi (MIT) and rumdl (MIT). Their license texts are vendored in
`crates/lume-language-servers/assets/licenses/` and copied into that bundle's license folder.
Private packages assembled after `build_release_bundle.ps1 -SoloExe`, and the current Unix
packages, do not include these server binaries; consult each package's README and build metadata.

## tiberius-ng (modified)

- Project: [tiberius-ng](https://crates.io/crates/tiberius-ng)
- Version: `0.13.1`, vendored from the crates.io release tarball
- License: MIT OR Apache-2.0
- Vendored licenses: `vendor/tiberius-ng/LICENSE-MIT.txt`,
  `vendor/tiberius-ng/LICENSE-APACHE.txt`

**This copy is modified.** Apache-2.0 §4(b) requires stating the changes; each modified file also
carries a notice at the top. Diffed against the crates.io tarball for `0.13.1`, exactly two files
differ from upstream:

- `Cargo.toml` — the `rustls` feature depends on `rustls-platform-verifier` instead of
  `rustls-native-certs`.
- `src/client/tls_stream/rustls_tls_stream.rs` — `with_native_roots` builds the client
  configuration with the platform certificate verifier (the operating system's trust store,
  corporate CAs included) instead of loading the native roots by hand.

The reason is a single trust policy: `reqwest` and this crate both verify server certificates
through `rustls-platform-verifier`, so a certificate authority installed in the operating system
applies to updates, language-server downloads and Azure SQL alike, and there is one place to add
one. The exception is Oracle: `oracledb` embeds the `webpki-roots` list in its own code, so a
private CA is not honoured for Oracle connections (a limit, not a choice).

Two removals, both of material that cannot run from here (the crate is a `[patch]` path dependency,
not a workspace member, so its tests and examples are never built):

- `docker/` and `docker-compose.yml` — the upstream integration-test rig. Its `certs/` directory
  contained real PEM private keys (test fixtures generated by upstream's own scripts, but secret
  scanners do not make that distinction).
- `tests/custom-cert.rs` and its `[[test]]` entry — it needs those certificates.
